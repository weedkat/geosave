# Lazy raster chips

Chips lays fixed-size tiles over georeferenced sources and merges predictions
back. It owns three things: the Tiler layout per source, flat index ↔
`(sample_index, tile_id)` keys, and native Merger reconstruction.

```python
chips = gs.Chips([scene], size=224, overlap=32, mode="reflect")
chip = chips[3]                    # scene.gs.crop_to_grid(chips.geobox(3), mode="reflect")
chip.time                          # observation dates, unchanged
chip.gs.region.extent.centroid     # chip location
pixels = chip.gs.to_numpy(dtype="float32")

outputs = chips.merge((key, predict(chips[key])) for key in chips)
```

`Chips(samples, size, overlap=0, *, mode="constant", constant_value=0)`

Each sample is a Dataset or DataArray on one regular grid. Construction reads
only grid metadata. Indexing returns a lazy xarray chip and computes nothing.
Iteration yields keys.

## Chip selection belongs to `gs.crop_to_grid`

`transform/extent.py` owns `crop_to_grid(data, geobox, *, mode, constant_value)`.
It is exposed as `ds.gs.crop_to_grid` and `da.gs.crop_to_grid`. It takes exactly
the pixels of a grid aligned with the source: same CRS, same pixel size, and a
whole-pixel offset. It pads where that grid leaves the source.

Native `isel` already keeps laziness, time and other coordinates, variable
attrs, and coordinate-derived grids (`gs.geobox`, `rio.transform()`). It leaves
two things stale. `crop_to_grid` fixes both:

| Native `isel` leaves | `crop_to_grid` writes |
| --- | --- |
| `geospatial_bounds` of the whole scene (root and per variable), so `gs.region` names the scene centroid | Extent clipped to the chip grid, or cleared when they do not meet |
| `spatial_ref.GeoTransform` at the scene origin | Grid mapping of the chip grid |
| A clipped window at edges | Padding through `pad`, so the shape is always exactly `geobox` |

Padding applies to the overlapping pixels, as Tiler pads its tiles. Dask
returns the wrong shape for reflect and wrap padding wider than the axis, so
`pad` selects `np.pad(arange(n), widths, mode)` positions instead; this stays
lazy. Constant padding uses `constant_value` and keeps the dtype.

The geometry `gs.crop(region)` stays separate: it cuts to ground, may mask and
never pads. `read_pixels(geobox)` stays separate too: it resamples onto any grid
and computes.

## Merging

`merge(predictions, *, window=None)` takes `((sample_index, tile_id), pixels)`
pairs in any order, with spatial axes trailing. Leading shapes must agree within
a sample. Repeated tiles accumulate and missing tiles are allowed; Merger owns
normalization and fills uncovered pixels with zero. It returns one float32
NumPy array per sample, or None for a sample without predictions. Callers place
an output with `xr.DataArray(...).gs.write_grid(sample.gs.geobox)`.

Merging allocates full output accumulators (open item C5).

## Removed from the preceding design

- **NumPy chips and `dtype=`.** Conversion is `chip.gs.to_numpy(dtype=...)` in
  the caller's torch Dataset, which also reads model context from the chip.
- **`__getitems__` and `max_block_bytes`.** DataLoader batch reads no longer
  share Dask chunks across chips. A caller can still do this with
  `dask.compute(*[chips[i] for i in batch])`. Fast repeated loading is the job
  of the sample cache below, not of Chips.
- **Unreferenced pixel arrays.** Every sample needs a regular grid.
- **Zero-filled merges for sources without predictions.** These now return None.

## Deferred: sample caching

Caching is a separate mechanism, not Chips state. It stores the samples a
method's torch Dataset returns (tensors plus context), not chips or sources.
Decide storage format, keys, invalidation, worker behavior and lifetime in its
own design. The previous [storage](../benchmarks/2026-11-06-chip-storage/index.md)
and [mapping](../benchmarks/2026-11-07-chip-memory/index.md) measurements are
historical evidence for the removed chip stores.

The independent `workspace/gedi-biomass` project still consumes saved chip
stores and needs migration.
