# GeoSave project review — 2026-11-04

## Performance follow-up

The [measured performance report](benchmarks/2026-11-04/index.md) adds **97 timed
cases** covering raster open/write, NetCDF/native baselines, tree conversions,
decoding, NDVI, same-CRS resampling, true cross-CRS warps, NumPy/tensor conversion,
chip layout/read, cropping/chunk sensitivity, and catalogs up to 5,000 Items.
It includes repeat-level JSON and four runnable scripts. Zarr workers timed out
for both GeoSave and native xarray; those are not successful timing cases.

The strongest measured optimization target is multiband COG access: the same
32 MiB pixels read as one rioxarray multiband array in 129 ms versus 501 ms as
separate variables without Dask. GeoSave default open-to-tensor took 877–955 ms
across the controlled/main runs. Investigate shared reads and chunk scheduling
while retaining native Dataset values and per-band metadata. Tree wrapping
(~0.74 ms) and same-grid conversion (~3.48 ms) do not justify new abstractions.

The cross-CRS comparison also strengthens #14: lazy **nearest** output differed
at 64,992 / 2,113,983 compared valid pixels, while eager GeoSave matched the
whole-array Rasterio reference on those pixels. Lazy bilinear also differed,
and both lazy masks disagreed at 178 pixels. These are high-frequency synthetic
fixtures, not blanket real-data accuracy estimates. Preserve the reproducible
case and resolve the numerical contract before throughput optimization.

Production code remains unchanged; benchmark scripts are review artifacts.

## Scope and conclusion

This review examines the **current, heavily modified working tree**, not a clean
release or a comparison against HEAD. Findings are current failures or design
risks, not claims that this review introduced or identified historical regressions.
Only documentation was edited. Library code, CLI implementation, templates,
tests, configuration, and notebooks were left unchanged.

The native-object direction is sound: keep xarray, GeoPandas, PySTAC, Lightning,
and project-owned training code. The largest current problems are incomplete
migrations across those boundaries and insufficient validation of the full user
workflow. Adding another framework would make those problems harder to see.

The offline raster → COG → catalog → samples → chips workflow runs. The plain
Lightning starter trains on CPU, and local registered-model release tests pass.
The geospatial training starters and catalog-to-ModelSpec preparation currently
fail. Several smaller data-integrity problems deserve attention before broader
API redesign or more templates.

**Priority:** P1 blocks an advertised workflow or risks incorrect data/security;
P2 materially improves robustness, usability, or maintenance; P3 is cleanup.
**Scope:** S is a localized change; M crosses several modules or consumers;
L needs a staged compatibility or packaging decision. These are relative sizes,
not delivery estimates. “Reproduced” means a local smoke or test demonstrated the
behavior; “source-confirmed” means the relevant execution path was inspected;
“proposal” requires measurement or a design choice before implementation.

## Second pass: the paradigm behind the findings

The second pass re-read `AGENTS.md`, `GLOSSARY.md`, current architecture and open
decisions, the project-owned training design, and the later native construction,
I/O/STAC ownership, nested-tree, and Explorer-loading designs. Those documents
are not all equally current: for example, older sampling plans describe a
`region` column or list-valued sample rows that the live implementation no
longer uses. Recommendations below follow live source plus the latest explicit
ownership decisions, not an instruction to restore every old proposal.

### What the library contributes

```python
# Native values; GeoSave supplies operations and geospatial meaning.
scene = xr.Dataset({"red": (("y", "x"), pixels)}).gs.write_grid(grid)
items = scene.gs.to_catalog(output, collection="optical", datetime=observed)
samples = items.gs.sample(pair=["optical"], window=2)
tree = samples[0].gs.to_datatree()
chips = gs.Chips([tree], size=128, resolution=10)
_, chip = chips[0]
raster = chip["optical"].gs.to_dataset()
```

This is a schematic composition, not an additional runnable tutorial: `pixels`,
`grid`, `output`, and `observed` are application inputs and a two-slot sample
needs two observations. The important design is that each value remains usable
through its native interface. The public entry point is not a custom pipeline
object that owns all subsequent processing.

| Concept | Its invariant and owner | What it must not silently decide |
| --- | --- | --- |
| Raster | Native xarray values, coordinates and grouped attrs; accessors add operations. | Reprojection, decoding, eager computation, or wrapper-only access to pixels. |
| GeoAnchor | CRS-aware geometry and temporal coverage, independent of a pixel lattice. | Resolution, output shape, or a default model grid. |
| GeoBox | Exact CRS, affine transform and shape. | Which observations belong in a sample. |
| Item / Collection | STAC observation/assets and collection metadata, convertible to native table rows. | An Item row is not a table of the pixels or feature records inside its assets. |
| Region | Geographic support of a sample, founded from the smaller footprint and joined by sufficiently covering Items. | The union of the full source-file footprints is not necessarily that Region. |
| Pair / Slot / Window | Paired observations, their temporal placement, and consecutive slots; GeoCatalog plans membership. | A temporal interval is not timeless merely because STAC `datetime` is null. |
| GeoSamples | One Item table plus row positions for each sample; rows can belong to several samples. | A pandas GroupBy cannot directly represent that overlapping membership. |
| DataTree | Collections over grid nodes, preserving native resolutions and observation metadata. | Naming a collection does not align all its grids or choose a model resolution. |
| Chips | One layout per sample tree, lazy chip reads, and accumulation back onto that layout. | Completeness of predictions cannot be inferred from “one output arrived for this tree.” |
| ModelSpec | Raster requirements, explicit processing, named inputs/context and tensor-transform declarations. | It does not execute the model, automatically normalize release inputs, or own the training loop. |
| ModelChain | A native PyTorch Module with declared name/type dataflow and optional reconstructable stage recipes. | Construction order and dataflow order are distinct; a visualization must describe the executed graph. |
| Generated method | Project-owned Dataset, DataModule, Module and sample contract; Lightning runs the loop. | A library recipe hierarchy must not take back experiment ownership or couple two generated methods. |
| Release | Reconstructable registered architecture, trained weights and optional processing declaration. | A checkpoint, live workspace, and deployed inference contract are not interchangeable artifacts. |

A `GeoSamples` object and a `Chips` object are justified here: they own
relationships and state that a single native table/raster does not express.
This does **not** justify wrapping every raster or inventing a new Dataset
framework. The same reasoning supports the small `GeoAnchor` value, while exact
pixel placement remains a native GeoBox.

### Four distinct promises of laziness

1. **Metadata-only planning:** catalog sampling and chip layout should not
   execute pixel tasks.
2. **Deferred pixel work:** a Dask-backed raster transformation builds work
   until compute/write/tensor conversion requests it.
3. **Bounded I/O:** requesting a chip should avoid transferring an entire remote
   file where the backend supports ranges. A deferred array alone does not prove this.
4. **Bounded numerical work:** reprojecting one requested chip should retain
   the required interpolation neighbourhood and valid metadata without silently
   computing the entire scene.

A fresh second-pass smoke verified native runtime aliases, no torch import from
`import geosave`, and **zero Dask tasks** through construction → collection tree
→ single-collection Dataset → decode → chip selection. A separate published
catalog → sample → open tree → chip selection also executed zero pixel tasks;
explicit computation returned the expected values. These are strengths to
preserve. Remote transfer cost and the known warp xfails remain separate limits.

### Which source of truth wins

| Handoff | Required meaning | Current tension |
| --- | --- | --- |
| Item metadata → file read | Native asset opening prefers the real file grid when catalog projection disagrees. | Viewport pruning can trust the stale catalog first and hide valid pixels (#23). |
| Sampling → tree → Chips | Sample membership, geographic Region, and temporal support must stay distinguishable. | Region support is lost before a union-based chip layout; interval Items can be treated timeless (#24–25). |
| Dataset → batch → model | Channel order, units, target validity, transforms and context must refer to the same observation. | Default RGB meaning (#6), loss denominators (#28), and spec provenance (#7) need explicit checks. |
| Chain declaration → execution | Routing and displayed dependencies must agree. | Optional produced inputs can depend on insertion order (#27). |
| Location argument → storage | Protocol and options survive until the single location conversion owner. | Flow CLI converts URLs to local `Path` spelling first (#26). |

### Recommendations reconsidered

- **Withdraw #21's sampling move.** The current architecture deliberately puts
  sample planning on GeoCatalog and the resulting index relation on GeoSamples.
  Its line count is not evidence that this ownership is wrong. The deeper
  problem is preserving Region and temporal meaning across their interfaces.
- **Keep method-local duplication where it protects independent editing.**
  FixMatch and Mean Teacher own local supervised bases. Consolidating them
  into a library-owned training superclass would reverse an explicit decision.
- **Keep the two raster-loading paths when their semantics differ.** Native
  Item opening preserves original grids; ODC loading explicitly groups, fuses
  and resamples selected Items onto a requested grid. Unifying the names or
  implementation solely because both read STAC would erase a useful distinction.
- **Do not restore a grid-bearing anchor or window settings on ModelSpec to
  patch migration failures.** The latest ownership design separates geometry,
  exact grids, catalog membership, and raster chips. Repair callers coherently.
- **Do not treat intentional scaffolding as a bug.** Geospatial Dataset stubs
  are deliberately project-owned extension points. The onboarding gap is a
  missing complete reference example and currently invalid generated configs,
  not the absence of a generic library Dataset.
- **Do not standardize all errors/warnings or attr combination into one policy.**
  Missing data, incompatible pixel semantics, unsupported configuration, and
  unavailable services have different consequences. Preserve native errors
  where meaningful and add context at the owning operation.

The most valuable changes therefore preserve semantic information at a handful
of handoffs. Moving files or adding validation everywhere is secondary.

## Urgent correctness and workflow repairs

### 1. Finish the chip-setting migration across all geospatial recipes

**P1 · M · Reproduced.** All six shipped geospatial `model_spec.yaml` files
contain `chips`, while `src/geosave/model/spec/model.py:102–107` does not define
that field. All six fail `ModelSpec.load`. Removing the field alone is
insufficient: eight DataModule implementations, counting the local supervised
bases, still read `self.spec.chips`. See
`src/templates/tasks/segmentation/supervised/modules/segmentation/supervised/data.py:99–103`.
The template/flow test run has 31 failures from this mismatch.

**Change:** settle the narrow owner of training/augmentation image size; update
all method configs, DataModules, preparation scripts, and documentation as one
migration. Keep independent method copies, as required by project ownership.
Do not restore an obsolete compatibility field simply to satisfy old callers.
The broader ModelSpec redesign remains on hold.

**Risk/dependencies:** existing generated workspaces need explicit migration
instructions; library upgrades do not update copied files. Coordinate with #2,
but neither repair needs custom-code publication decisions.

**Acceptance:** load every shipped YAML, generate every method independently,
and run a tiny CPU training and validation batch for each supported method.
Run the generated segmentation preparation script. Failures must identify the
method rather than stop a single all-method loop at its first failure.

### 2. Make ModelSpec preparation select collections and grids explicitly

**P1 · M · Reproduced.** `ModelSpec.prepare` reads `tree.gs.rasters`, then
expects bare names such as `optical` and `label`
(`src/geosave/model/spec/model.py:310–316`). Catalog loading now returns
`optical/r10m` and `label/r10m`. Five model-spec tests fail: even a valid
single-grid catalog cannot complete preparation; `keep=["label"]` reports a
missing label collection.

**Change:** let a declared model raster select its collection and choose an
explicit grid when necessary. Keep the collection/grid hierarchy native.
Blindly stripping suffixes would lose information when a collection has more
than one grid. Keep selection and alignment ownership clear between ModelSpec
and geodata, without expanding the deferred processing language.

**Risk/dependencies:** ambiguous multi-grid input must not silently choose a
resolution or resample labels. Agree on the existing hierarchy contract first.

**Acceptance:** ingest/publish → catalog round trip → prepare → model inputs,
with one and multiple grids, a retained label, exact values/placement, and
laziness before the explicit write.

### 3. Reject or preserve mixed DataTree hierarchies before publication

**P1 · M · Reproduced.** In `src/geosave/geodata/io/paths.py:159–170`,
`split_by_collection` returns only root children that themselves have children
when any such child exists. A tree containing `s2/r1m` and a raster leaf
`labels` exposes both through `.gs.rasters`, but path expansion emits only
`s2/red.tif`. `io/stac.py:306–319` uses this split as well. A valid native
container can therefore lose a raster during COG/catalog publication.

**Change:** define the accepted hierarchy once at the publication interface.
Either enumerate every supported raster leaf or reject a mixed hierarchy
before planning any writes. Prefer an explicit validation error over guessing
which leaves belong to a collection.

**Risk/dependencies:** validation may newly reject trees previously accepted
with data loss. Keep collection IDs, grid names, and output filenames distinct.

**Acceptance:** mixed leaf/nested and root-data examples either preserve every
raster on round trip or fail before creating assets. Reuse the check across
COG and catalog publication.

### 4. Detect incomplete chip predictions before merging

**P1 · S/M · Reproduced.** `Chips.add` tracks merger state per tree, and
`Chips.merge` only checks that each tree received some output
(`src/geosave/geodata/core/raster/chips.py:113–127,152–170`). Supplying one of
four chips produces ordinary zeros over the unprocessed 75% of the raster.
Those zeros have no missing-coverage marker and can look like valid predictions.

**Change:** track coverage by chip index. Require complete coverage by default,
with an explicit partial-result policy only if a real caller needs one.
Define duplicate-add behavior as part of the same interface. Keep this state
on `Chips`, which already owns the layout and accumulation.

**Risk/dependencies:** callers relying on partial merges will need to opt in
or complete their predictions. No new wrapper is necessary.

**Acceptance:** missing, duplicated, shuffled, and complete chip submissions;
complete predictions reproduce expected values/grid, while missing coverage
cannot become plausible class-zero output silently.

### 5. Make local file staging safe against overlapping writers

**P1 · S/M · Reproduced race; collision risk source-confirmed.**
`src/geosave/geodata/io/storage.py:161–180` checks existence, writes to the
fixed `.<stem>.staging<suffix>`, then calls `os.replace`. A destination created
inside the save callback is replaced even with `overwrite=False`. Two writers
also share the same staging filename.

**Change:** use unique staging files and a publication operation whose
no-overwrite semantics hold at commit time. Define backend-specific guarantees
for remote uploads rather than promising transactions across many assets.
Keep staging/promotion in storage; formats should only encode their files.

**Risk/dependencies:** local filesystem atomicity and remote object-store
conditional writes differ. Preserve useful failure cleanup and original files.

**Acceptance:** two coordinated writers, destination appearing after preflight,
encoder failure, and explicit overwrite. The loser must not replace or remove
the winner's data; unrelated staging files must survive.

### 6. Preserve pretrained channel meaning in the default recipes

**P1 · S · Source-confirmed; accuracy impact unmeasured.** The supervised
segmentation spec orders Sentinel-2 channels `[B02, B03, B04, B08]`
(`src/templates/tasks/segmentation/supervised/configs/segmentation-supervised/model_spec.yaml:4,13`).
The selected DINOv3 adapter defaults to pretrained weights and documents the
first three pretrained channels as red/green/blue
(`src/geosave/model/stages/encoder/dinov3.py:41,57–62`). Blue/green/red/NIR
therefore misaligns the RGB kernel slices.

**Change:** choose a deliberate RGB/NIR order and move normalization statistics
with their corresponding bands, or explicitly adapt/reinitialize the input
weights. Apply the decision to all recipes sharing that source configuration.

**Risk/dependencies:** this changes the training input contract; do not reorder
inputs to already-trained artifacts without their original spec. Repair #1 first.

**Acceptance:** distinguishable synthetic band values prove channel and
normalization order; inspect the adapter's channel initialization without a
large model download.

### 7. Bind published preprocessing and source files to the training run

**P1 · M · Source-confirmed.** Each publisher loads a checkpoint but reads
ModelSpec from the currently editable workspace config, for example
`src/templates/tasks/segmentation/supervised/scripts/segmentation/supervised/publish.py:32–40`.
The DataModule loads a spec while Module hyperparameters do not capture its
contents (`.../data.py:91`, `.../module.py:75`). Editing band order or
normalization after training can silently attach the wrong contract to weights.

The second pass tested the installed Hugging Face file matcher offline.
Its current patterns retain `data/private.py`, `artifacts/run/replay.py`,
`modules/segmentation/.env`, and `configs/service-account.json`. In particular,
`*.py` is not restricted to root-level Python files. The exclusion claim is
therefore demonstrably false, not merely a hypothetical upload concern.

The publisher also uploads broad `configs/**`, `scripts/**`, and `modules/**`
globs, despite claiming credentials/data/logs never upload. The model and
workspace are separate Hub operations, so the first can succeed without the
second. The copied workspace may not be the version that produced the run.

**Change:** snapshot the effective spec and selected method/run configuration
with the run, record provenance, and stage a concrete release manifest locally.
Publish that snapshot, not live working files. Restrict included files to the
selected artifact; either use one commit or expose the two-stage state clearly.
This is reproducibility work, not permission to redesign executable code trust.

**Risk/dependencies:** old checkpoints may lack provenance; require an explicit
reconstruction decision rather than inventing it. Uploaded layout may change.

**Acceptance:** train/save, edit workspace settings, then export locally and
verify the original contract survives or ambiguity is rejected. Check planned
uploads with unrelated files and simulate a second-stage failure. No live Hub
write is needed for these tests.

### 8. Remove the generic TLS bypass and make environment loading predictable

**P1/S for TLS; P2/S for lookup · Source-confirmed and locally reproduced.**
`src/templates/common/.env.example:8` sets `GDAL_HTTP_UNSAFESSL=YES` for every
workspace, alongside provider-specific placeholder settings. This is not an
appropriate default for a general or offline starter.

`src/geosave/cli/main.py:18–21` calls bare `load_dotenv()` despite promising
current-directory lookup. A real temporary-process smoke placed a unique
marker in the working directory's `.env`; CLI creation succeeded but did not
load the marker. Generated `src/templates/common/main.py` does not load that
file either.

**Change:** remove TLS bypass from shared templates; document provider-specific
settings only where needed. Choose the startup owner of workspace environment
loading and use an explicit path, retaining externally supplied environment
precedence. Do not accidentally discover configuration in the installation tree.

**Risk/dependencies:** environment lookup is observable behavior. Document
whether parent directories are searched; users with certificate issues need a
proper trust configuration.

A second-pass probe using the actual `.venv/bin/geosave` console executable
also failed to load a unique working-directory `.env` marker. This is not
specific to `CliRunner`.

**Acceptance:** fresh offline projects contain no TLS bypass; subprocesses in
two different workspaces read only their own environment settings. CLI and
training startup follow the same documented rule.

## High-value simplifications and robustness work

### 9. Gate releases on actual consumer workflows

**P1 · M · Source-confirmed.** The repository has docs and release workflows,
but no test workflow gating release. `.github/workflows/release.yml:100–134`
builds/publishes without test dependencies, an installed-wheel smoke, or a
check that the release tag matches the packaged version. Source-checkout tests
cannot prove templates were included correctly in the wheel.

**Change:** add PR validation and make publication depend on an offline
correctness suite plus an installed-wheel create/train/release smoke outside
the source checkout. Check tag/version agreement. Separate external-service
checks rather than making credentials a prerequisite for every PR.

**Risk/dependencies:** explicitly resolve the current failures (#1–2) rather
than weakening gates to manufacture a green build.

**Acceptance:** failing tests and mismatched tags prevent publication; the
actual built artifact creates every method outside the checkout. Hosted Actions
and publication were not executed in this review.

### 10. Give generated workspaces a small reproducibility contract

**P2 · M · Source-confirmed and generation inspected.**
`src/geosave/cli/core/workspace.py:21–29` copies startup files but generates no
dependency manifest, generator version, or root setup README. The project
silently depends on whichever environment launches `main.py`.

**Change:** include a minimal dependency manifest, recorded generator version,
and exact setup/run instructions. Choose an initial pin or compatibility range
explicitly. Preserve existing manifests under `--force`; do not introduce an
automatic template-upgrade framework. Fix `.gitignore` separately: it currently
ignores checkpoints but not all `artifacts/` logs and saved configs.

**Risk/dependencies:** coordinate packaging extras (#11) and migration guidance
(#1). Generated files remain user-owned.

**Acceptance:** a new project installs and runs the offline starter in a fresh
environment independently of the repository environment.

### 11. Slim dependency installation and selected-model imports

**P2 · M/L · Proposal supported by source; footprint unmeasured.**
`pyproject.toml:25–86` puts the visualization/notebook stack and cloud masking
in the base install; `hub` pulls the whole training extra. `tomlkit` is a direct
dependency with no production import found. Building a small registered head
loads built-in stage registration (`model/registry.py:240`), and
`model/stages/encoder/__init__.py:1–4` imports unrelated encoders, including
TerraTorch-backed implementations.

**Change:** measure fresh-install size and import cost by workflow. Remove
verified unused requirements; consider coherent visualization/masking extras
and a lighter inference/release dependency set. Resolve built-ins by selected
name where that avoids importing unrelated backbones. Keep the registry simple.

**Risk/dependencies:** extras are public installation contracts; update docs
and wheel smoke environments together. Do not infer that absence of a direct
import proves a dependency is unnecessary in every execution path.

**Acceptance:** isolated base, visualization, training, and Hub environments
perform their promised tasks without undeclared dependencies. Compare installed
size/import time before accepting the split.

### 12. Preserve bounded remote COG reads with credentials

**P2 · M · Source-confirmed; transfer cost unmeasured.**
`src/geosave/geodata/io/rasterio.py:127–134` localizes a nonlocal raster whenever
`storage_options` are present. Even anonymous access or endpoint options trigger
a whole-file download before lazy/window reads. Without options, GDAL can use
range reads. Laziness of the resulting array is not bounded network I/O.

**Change:** support credential/session translation for range-capable backends
where dependencies already provide it; retain an explicit documented download
fallback where necessary. Keep provider adaptation with the reader/storage seam.

**Risk/dependencies:** credential isolation and GDAL environment lifetime must
be verified; avoid process-global changes affecting outstanding lazy reads.

**Acceptance:** a controlled HTTP/object-store fixture records requested ranges
and transferred bytes for a small window with credentials/options. Test cleanup
and fallback separately. Documentation now states the existing behavior.

### 13. Resolve the meaning of nodata before concatenating observations

**P2 · M · Reproduced, intentional existing behavior.**
`src/geosave/geodata/transform/temporal.py` combines attrs; the contract in
`tests/geodata/transform/test_temporal.py:280–313` drops conflicting nodata
metadata with a warning while leaving stored pixels unchanged. A formerly
missing zero can then be treated as a valid measurement.

**Change:** explicitly decide whether temporal concatenation should reject
incompatible encodings or require callers to decode/normalize them first.
Keep generic grouped `combine_attrs` behavior intact; it has independent,
intentional semantics. This recommendation is a contract change, not a routine
bugfix to apply silently.

**Risk/dependencies:** callers currently accepting the warning may need an
explicit decode step. Preserve laziness and integer label meaning.

**Acceptance:** conflicting nodata/packing examples cannot silently turn missing
observations into valid values; atomic attr-group behavior remains covered.

### 14. Quantify and resolve the known lazy-warp discrepancies

**P2 · M · Existing expected failures confirmed.**
`tests/geodata/transform/test_warp.py:447–460` marks three lazy EPSG:3857 warp
comparisons as xfail for bilinear/cubic/average differences against full-grid
Rasterio. The focused run reports all three xfails; it is not an entirely green
numerical-validation suite.

**Change:** reduce each discrepancy to a small example, measure spatial error
and seam behavior, and decide a supported strategy or explicit limitation.
Pursue an upstream fix if warranted by that evidence. Do not solve it by silently
materializing the entire raster.

**Risk/dependencies:** interpolation tolerances must come from the domain and
reference behavior, not be enlarged solely to pass a test.

**Acceptance:** computed values, nodata edges, and grids satisfy the documented
contract across chunk boundaries while construction remains lazy.

### 15. Simplify repeated catalog metadata lookup and clarify its owning module

**P2 · S · Source-confirmed; performance unmeasured.**
`src/geosave/geodata/stac/search/table.py:67–72` calls `collection(identity)`
per collection. Each call reads collection metadata through `_read_collections`
(`:139–164`), repeating derived collection and footer queries.

**Change:** load metadata once for that search and select from the resulting
mapping. This concentrates work in the search module and does not need a
persistent cache with invalidation rules. Keep Item/table conversion with STAC,
asset reads with I/O, and predicates with search.

**Risk/dependencies:** preserve missing-collection errors and current filtering.

**Acceptance:** a representative multi-collection search returns identical
Items/Collection metadata with one metadata acquisition per search; measure
query count or elapsed work before claiming a speedup.

### 16. Make generated file copying fail before leaving partial recipes

**P2 · S/M · Source-confirmed risk; fault injection not run.**
`src/geosave/cli/core/copy.py:62–89` resolves conflicts while copying, while
`core/workspace.py:15–18` considers recipe path/config presence evidence that a
method is installed. An interrupted or partially skipped copy can become
unretryable through ordinary `add-task` selection.

**Change:** plan destination files/conflicts before mutating them, then apply
that plan. Keep conflict policy and copying together; do not add a parallel
installer abstraction. Clearly define recovery after an I/O failure.

**Risk/dependencies:** preserve existing user files and interactive choices;
preflight does not imply rollback after all possible storage failures.

**Acceptance:** cancellation, conflicting file, and injected write-failure cases
leave either an intact method or an actionable retry path.

### 17. Make worker and release integration assumptions testable

**P2 · S/M · Source-confirmed risks, not current Linux failures.**
Geospatial DataModules hardcode `multiprocessing_context="forkserver"` when
workers are enabled (representative `.../segmentation/supervised/data.py:112`).
The platform may not provide that context. Separately,
`src/geosave/model/release/huggingface.py:176–198` overrides Transformers'
private `_finalize_model_loading` hook across a broad supported version range.

**Change:** select a supported worker context deliberately and test real
nonzero-worker reads; keep protection against inheriting live raster handles.
For releases, prefer a supported loading-info interface if adequate, or document
the private dependency and exercise minimum/latest supported versions.

**Risk/dependencies:** worker startup changes pickling and performance; loader
changes must preserve strict weight validation. No artifact-format change is
needed merely to isolate the integration.

**Acceptance:** generated loaders on supported platforms; compact release tests
cover exact outputs, missing/unexpected weights, nonpersistent buffers, and a
fresh process. Windows was not exercised here; local release tests pass.

### 18. Maintain a small executable onboarding path

**P2 · M · Confirmed docs drift; implementation proposal.** Current API-reference
freshness checks catch generated text drift, but not incompatible hand-written
examples. The review found both obsolete API calls and an impossible transition
from a custom `class_path` training model to registered native release.

**Change:** maintain one bounded offline workflow for each major promise:
raster round trip; catalog/sample/chip read; generated training; registered
release round trip. Reuse the real public interfaces and test saved artifacts,
not exact Markdown strings. Keep partial snippets visibly labeled. After #1–2,

## Further module ownership decisions

### 21. Sampling-module move withdrawn after ownership review

The first pass suggested moving sampling beside `GeoSamples` based on accessor
size. Re-reading the current design and tracing Region/Pair/Slot/Window planning
shows that GeoCatalog is the declared owner, while GeoSamples owns the shared
Item-row positions. There is no demonstrated benefit from a move alone.
Preserve this ownership and address the actual geographic/temporal handoff
problems in #24–25. This is not an implementation task.

### 22. Separate readable grid names from grid identity if broader assets are supported

**P2 · M · Source-confirmed limitation; no reproduced data loss.**
`core/raster/grid.py:132–142` names grids using x-resolution and unit;
`io/stac.py:50–66` groups assets by that name. Different lattices with the same
resolution are not necessarily the same grid and can fail during combination.

**Change:** first decide whether scene assets must share one exact lattice per
resolution. Validate and document that restriction if intentional. If broader
inputs are needed, group by actual grid identity and assign readable unique
node names. Avoid implicit alignment disguised as grouping.

**Risk/dependencies:** grid-node names are visible to callers and persisted
hierarchies. Coordinate with #2–3; do not rename them casually.

**Acceptance:** shifted origins, anisotropic resolution, and different CRSs
with equal nominal resolution either produce distinct supported nodes or a
clear early error, with no unrequested resampling.

## Deeper findings at the semantic handoffs

### 23. Use one grid-authority policy for native reads and viewport reads

**P1 · S/M · Reproduced with a real COG.**
`src/geosave/geodata/io/stac.py::_place_on_stated_grid` prefers the file's grid
and warns when STAC projection metadata disagrees. `_read_asset_pixels`,
however, returns early when the **stated** grid misses the requested view,
before opening the file and applying that policy.

A 4×4 COG of ones with deliberately stale `proj:transform` was readable through
`open_scene`: sixteen ones, with a disagreement warning. The same Item and
actual file grid through `read_scene_pixels` returned sixteen NaNs. Explorer
can therefore report absence where the native reader sees data.

**Change:** decide when catalog projection is authoritative enough for a
no-open exclusion. Otherwise validate/cache the actual file grid before
negative pruning. Keep this in geodata pixel reading; do not fix it by adding
a separate viewer reader or disabling all useful metadata pruning.

**Risk/dependencies:** correctness versus header-request cost is an explicit
tradeoff. An authoritative-metadata option would itself need a clear contract.

**Acceptance:** conflicting catalog/file projections have consistent supported
behavior across ordinary and viewport reads; truthful non-overlapping metadata
still avoids unnecessary pixel reads. Verify missing-grid fallback separately.

### 24. Preserve Region support across sampling, loading, and chip layout

**P1 · M · Reproduced with real adjacent COGs.**
`core/vector/catalog.py:639–648` identifies Region footprints but returns only
row memberships. `core/vector/samples.py:36–47` stores those positions;
`.footprints` recomputes intersection from the selected Items. Catalog loading
opens full assets (`catalog.py:879–891`), and `Chips.lay_grid`
(`core/raster/chips.py:174–202`) takes their union.

```text
Optical A: x=0..40 m     Optical B: x=40..80 m
Shared radar: x=0..80 m; all heights 40 m, pixels 10 m

sample 0 = [A, radar], displayed footprint 40×40 m
sample 1 = [B, radar], displayed footprint 40×40 m

Each opened sample → Chips(size=4, resolution=10)
                   → the SAME 80×40 m layout, two chips
```

Both samples include the other Region, where their optical input is absent.
This expands training coverage and duplicates shared-source windows. The
computed intersection also cannot recover the founding Region if its smallest
Item was removed by temporal pairing.

**Change:** define the geographic Region handoff, retaining native geometry,
and make crop/target-grid selection explicit before Chips lays out pixels.
Sampling still owns membership without reading pixels or choosing resolution.
Do not silently redefine generic Item loading or GeoAnchor's union semantics;
the defect is the missing connection between distinct concepts.

**Risk/dependencies:** sample membership may remain unchanged while the spatial
support changes, so existing training runs need reproducibility consideration.
Coordinate with #2–4 and #30. Do not choose a new wrapper representation before
a small end-to-end smoke establishes the needed invariant.

**Acceptance:** two adjacent Regions sharing a larger swath keep distinct chip
extents, valid multimodal overlap, and lazy reads. Include a temporal selection
that excludes the Item which founded the Region.

### 25. Interpret composite intervals consistently during sampling

**P1 · S/M · Reproduced with valid native STAC Items.**
`core/vector/catalog.py:737–743` derives dates only from `datetime`, then
`:780–791` attaches undated Items to every Window. Meanwhile
`stac/item.py:330–350::read_instant` interprets interval-only Items using their
start date, and loading uses that helper.

A January composite with `datetime=None`, January `start_datetime` and
`end_datetime` joined **both January and February** optical Windows as though
it were a timeless DEM. Selecting that composite collection as the primary
`pair` instead produced no complete Window. `read_instant` correctly returned
January 1 for the very same Item.

**Change:** use the agreed STAC temporal interpretation across metadata sampling
and loading. Preserve the full interval; choose the nominal instant for Pair
and Slot placement explicitly. “Timeless” means absent temporal coverage, not
a null instant column. No additional time abstraction is needed.

**Risk/dependencies:** fixes observable sample membership; existing prepared
catalogs or experiments may need regeneration. Respect the existing timeless
sentinel convention and do not reinterpret it as a real ancient observation.

**Acceptance:** interval-only primary and partner Items, dated unpaired
collections, January/February separation, and true timeless DEMs. No pixel I/O.

### 26. Preserve URL protocols through the flows CLI

**P2 · S · Reproduced through CLI parsing with captured flow arguments.**
`src/geosave_flows/cli.py:30–40` accepts `output` and `spec` as `pathlib.Path`,
then converts them to strings before the flow reaches `storage.location`.

```text
s3://example-bucket/data          → s3:/example-bucket/data
hf://datasets/example/spec.yaml  → hf:/datasets/example/spec.yaml
```

The CLI capture exits successfully with those corrupted locations. This
violates the one-Location-code-path design and can turn remote output intent
into a local pathname. The Python flow already accepts path/URL strings.

**Change:** preserve strings at the CLI and delegate location interpretation
once to storage. Keep local path validation where it is actually required,
not in a generic remote-capable argument type.

**Risk/dependencies:** local/remote error presentation may change; callers must
not rely on silently rewritten URL spellings.

**Acceptance:** URL strings survive parsing byte-for-byte, including queries
and fragments where supported; local paths still work. Test captured arguments
without contacting remote services, then separately exercise supported storage.

### 27. Bind optional model dependencies before choosing execution order

**P1 · M · Reproduced on CPU.**
`src/geosave/model/chain/routing.py:43–51` orders only required inputs.
`Step.invoke` consumes optional inputs if present, and `ModelChain.to_mermaid`
draws their producer edges. A producer of `gain=image*2` and terminal consumer
`image + gain` with default `gain=None` behaves as follows on ones:

```text
ModelChain(producer=Producer(), consumer=Consumer()) → 3
ModelChain(consumer=Consumer(), producer=Producer()) → 1
Both diagrams show producer → consumer for gain.
```

**Change:** distinguish an optional external argument from an optional argument
bound to a selected producer. A bound dependency must affect ordering, or an
ambiguous/cyclic binding must fail. Keep named typed routing as the interface;
there is no need for a new graph/orchestration framework.

**Risk/dependencies:** optional-input ordering is observable. Define whether a
caller-supplied value overrides or conflicts with an internal producer rather
than allowing execution order to decide.

**Acceptance:** insertion-order-independent results for the same bound graph,
defaults when no producer exists, optional type conflicts/cycles, and diagram
agreement with actual execution. Preserve gradients through the routed values.

### 28. Aggregate validation loss over evidence, not empty images

**P1 · M · Reproduced against actual template methods.**
`src/templates/tasks/segmentation/supervised/modules/segmentation/supervised/module.py:231–238`
logs mean batch loss with `batch_size=len(target)`. Its loss is zero for an
all-ignore batch. With uniform binary logits:

```text
Fully labeled image: loss 0.693147, weight 1
All-ignore image:    loss 0,        weight 1
Resulting image-weighted mean: 0.346574
```

The actual validation method emitted those loss/weight pairs; their configured
image-weighted epoch mean is 0.346574. Adding no labeled evidence therefore
halves that score. This probe did not run a full Trainer epoch. Checkpoint
selection monitors that loss. Regression repeats this pattern after excluding
nonfinite targets (`.../regression/supervised/module.py:176–183`). Valid-pixel
density also changes the effective weighting between nonempty batches.

**Change:** define the monitored loss's statistical unit, accumulate its
numerator and matching denominator, and synchronize both across ranks.
Weighted criteria may have a denominator other than raw pixel count. Keep the
zero-gradient policy for empty **training** batches distinct from validation
aggregation. Apply the chosen behavior to method-local supervised copies too.

**Risk/dependencies:** logged values and possibly selected checkpoints change;
this is a meaningful correction, not a logging cosmetic. Do not substitute a
metric with different criterion semantics without saying so.

**Acceptance:** adding ignored labels/empty batches cannot improve validation
loss; repartitioning identical labeled evidence into batches or ranks leaves
the result unchanged. Verify finite gradients for empty training batches.

### 29. Define calibration's objective and artifact lifecycle together

**P1 · M · Numeric defect reproduced; distributed/lifecycle gaps source-confirmed.**
`src/geosave/ml/callbacks/calibrate.py:59–76` introduces a synthetic abstain
class and assumes `ignore_index` removes it from macro averaging. Ignoring a
target position is not the same as excluding that predicted class's score.

```text
truth:                         [1, 0, 0, 1]
prediction:                    [0, 0, 1, 1]
macro F1:                      0.5
suppress one incorrect guess:  [2, 0, 1, 1]
F1 over actual classes:        0.583333
current callback score:        0.388889
```

With confidences `[.55, .95, .55, .95]` and candidate thresholds `[0, .6, 1]`,
the sweep selects zero instead of the useful candidate for this example.

The same callback collects rank-local outputs (`:182–222`), calibrates on the
configured final epoch rather than necessarily the selected best checkpoint,
and stores thresholds on the LightningModule while publication exports its
chain. Inspected source does not apply those thresholds to predictions.

**Change:** specify the coverage/error tradeoff and calculate over actual
classes with explicit false-negative penalties. Then settle calibration
against the **selected** checkpoint, distributed evidence, inference application,
and persistence. A separate calibration step producing an explicit artifact is
a candidate to smoke-test, not an already approved design. Coordinate with the
existing open decision on head-owned prediction/calibration; do not move a
training callback into `model` by default.

**Risk/dependencies:** metric meaning and deployment predictions change. The
larger artifact choice needs review under existing model-publication decisions.

**Acceptance:** this counterexample, truly ignored targets, all-abstain and
no-abstain cases, agreement across rank partitioning, and inference equivalence
after saving/loading the selected model plus its calibration. Distributed
execution was not performed during this audit.

### 30. Make the same-grid and explicit-grid loading routes discoverable

**P2 · S docs / M only if API expansion is needed · Reproduced with real COGs.**
Sampling accepts Items with sufficient geographic overlap. Two successive
20×4-pixel acquisitions shifted one 10 m pixel overlap by 95%, so
`sample(pair=["s2"], window=2)` accepts them. Native `to_datatree()` then fails
with an x-coordinate `AlignmentError` while concatenating their scenes.
Alignment after opening cannot fix a failure that occurs during opening.

**Change:** retain exact-grid native loading—it prevents accidental resampling.
Document the explicit route through existing `io.load_dataset`/`load_datatree`
with selected native Items, a GeoBox and resampling policy. For multiple
collections, load each deliberately and retain their names; label resampling
must remain categorical. Do not merge the native reader and ODC loader merely
to remove an apparent duplicate interface.

**Risk/dependencies:** ODC grouping/fusion is a separate decision from catalog
Pair/Slot membership. State its grouping options when preserving observation
identity matters. Establish this route before proposing another reader API.

**Acceptance:** the shifted acquisitions load lazily onto the explicitly chosen
grid with expected edge nodata and dates. A focused smoke verified shape
`(2, 4, 20)`, the target grid, unchanged covered values, and nodata in the second
acquisition's uncovered first column.
