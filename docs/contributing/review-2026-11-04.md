Updated 2026-11-07 against the working tree. This is the single review queue,
consolidating the November 4 project audit, November 5 re-review, November 6
raster ownership and extent audits, and open decisions. The filename remains
stable for existing links. Old numeric, V and L IDs are retained below.

**Status:** Done = implementation inspected; Obsolete = the old proposal no
longer fits; Open = still needs checking or a decision; Deferred = explicitly
outside the current work. Done does not imply full-suite verification. Older
reproductions are historical evidence unless explicitly identified as rerun.
Checkboxes track work to discuss and verify, not automatic approval to implement.

## Next: finish the Chips contract

Implemented caller API (see [design](specs/2026-11-06-chips.md)):

```python
chips = gs.Chips([scene], size=256, overlap=32, mode="reflect")
chip = chips[0]  # lazy xarray via scene.gs.crop_to_grid(chips.geobox(0))
outputs = chips.merge(
    ((key, predict(chips[key].gs.to_numpy())) for key in chips), window="hamming"
)
```

- [x] **C1 — Window belongs to caller policy.** `merge` accepts a Literal of
  native Merger windows, None for uniform weights, or a tile-shaped NumPy array.
  Tiling modes are typed literals. Dependency validation is not duplicated.
- [x] **C2 — Native merging policy.** Repeated keys accumulate and missing
  predictions are allowed. Tiler owns normalization and uncovered-pixel behavior;
  no synthetic coverage channel or mandatory completeness check remains.
- [x] **C3 — Prediction meaning.** Merge returns NumPy arrays in source order.
  `chips.xarray[i]` retains original prepared sources; callers construct xarray
  outputs and choose relevant coordinates, labels, units and nodata.
- [x] **C4 — Indexing and lazy input reads.** Flat integer indexing supports
  map-style DataLoader batching. `chips.key(index)` supplies merge identity;
  explicit tuple access and keyed iteration remain available. Construction reads
  only metadata; `getitem` slices xarray before computing a NumPy chip through
  Tiler's callable reader. No full-source pixel cache remains.
  **50 focused tests passed**; [speed/memory measurements](benchmarks/2026-11-06-lazy-chips/index.md)
  show lower input memory with slower full scans. Targeted typing/lint passed.
- [x] Fractional overlap and padding values are passed directly to Tiler.
- [x] Leading dimensions retain `gs.to_numpy` ordering. Tiler flattens only its
  untiled channel axis; Merger supports independent output channel counts.
- [ ] **C5 — Output memory.** Merger still allocates full output accumulators.
  Decide streaming/disk-backed output separately; lazy input does not solve this.
- [x] **C6 — Batch read strategy.** Requested windows are computed together
  through Dask using a conservative byte budget, without custom spatial grouping.
  Index order, independent duplicates and native Tiler padding remain intact.
  The earlier [batch benchmark](benchmarks/2026-11-06-chip-batches/index.md)
  measured the preceding algorithm; its timings are historical.
- [x] **C7a — Model context.** Chips stays model-agnostic and returns lazy
  xarray chips from `gs.crop_to_grid`, which clips the declared extent and
  rewrites the grid mapping that native `isel` leaves stale. Time coords,
  nodata and attrs come with the chip, so a torch Dataset reads Prithvi-style
  temporal and location inputs from it. NumPy conversion, `dtype=`,
  `__getitems__` and `max_block_bytes` left Chips.
- [ ] **C7b — Sample caching.** Caching is a separate mechanism that stores a
  method's Dataset samples, not Chips state. See the
  [deferred contract](specs/2026-11-06-chips.md#deferred-sample-caching).
  The independent GEDI workspace still needs migration from saved chip stores.
- [x] **C8 — Obsolete: mapping residency.** The disk-backed implementation was
  removed with C7. The [storage benchmark](benchmarks/2026-11-06-chip-storage/index.md)
  and [mapping follow-up](benchmarks/2026-11-07-chip-memory/index.md) retain
  historical evidence; they do not describe current APIs. C5 output memory
  remains unresolved.
- [x] Fixed-size tile contract: `irregular` is removed and unsupported modes fail
  before source computation. Padding modes retain edge coverage; `drop` omits
  incomplete tiles. Focused Chips, expansion and model-processing checks:
  **67 passed, 5 warnings**; targeted Ruff, formatting and whitespace passed.

  then global default. Root and deep-node overrides are supported. Regression

  distinct numerical kernels with lazy inputs. No collection layout is inferred.
- [x] **R2 — Conversion use cases.** Current `core/raster/datatree.py:337-395`

  **8 passed, 41 deselected**. Duplicate-name rejection was source-inspected in
  `combine.merge`, not independently reproduced in this pass.
- [ ] **R3 / #14 — Lazy cross-CRS correctness.** Historical benchmarks found
  nearest differences at 64,992 / 2,113,983 valid pixels and 178 mask differences;
  eager output matched the full-array Rasterio reference. Existing interpolating
  warp xfails are not passing evidence. Reduce cases, compare chunk boundaries,
  masks and values, and establish tolerances before optimizing throughput.
  Current focused reproduction: **21 passed, 71 deselected, 3 xfailed, 10 warnings**
  in `test_cross_crs_pixels_match_explicit_rasterio_warp`. Lazy EPSG:3857 bilinear,
  cubic and average still disagree with the reference. This small fixture does
  not reproduce or dismiss the historical large nearest-neighbour discrepancy.
- [x] **R4 / #22 — Native grid naming collisions.**
  `core/raster/utils/grid.py:203-225` assigns distinct names for distinct exact
  grids; `io/stac.py:130` uses it. Fresh shifted-origin/anisotropic smoke produces
  `r10m`, `r10m_2`, `r10m_3`. This closes native reader grouping, not every use of
  a grid label: labels remain local names, not persistent spatial identities.
- [x] Concrete accessors own `region` and `write_extent`; shared base no longer
  reconstructs variant traversal. Shared derived grid properties remain useful.
- [x] `name_grid` / `name_grids` moved from I/O paths to raster grid utilities.
- [x] Alignment and reprojection both use ODC Geo’s `how: GeoBox | SomeCRS`.
  Explicit GeoBoxes stay exact: coverage changes and resolution overrides fail.
  CRS destinations support coverage planning; omitted resolution uses the finest
  same-CRS source pixel area. Mixed source CRSs require explicit resolution or a
  GeoBox. "native" is available only with a CRS destination and retains nested
  resolutions. `xr.align` remains coordinate alignment, not geospatial resampling.
  Breaking migration: `align(target=...)` becomes `align(how=...)`, and
  resampling keys must include full node paths with a leading slash.
- [x] Mixed-tree publication inventories data-bearing nodes and requires explicit
  collection assignment or rejects unsupported coverage before writes (old #3).

## Declared extent versus pixel grid

- [x] **Geographic terminology:** `GeoAnchor` is renamed to `GeoRegion`,
  `.gs.anchor` to `.gs.region`, and `set_anchor` to `set_region`. Geographic
  arguments and flow configuration types now use region, including CLI
  `--region`. Owning modules and the reference page are renamed. There are no
  compatibility aliases. ODC's pixel-placement `anchor` and calendar anchoring
  retain their meanings. Geometry/time behavior is unchanged; E1-E7 are not
  closed by this rename, and loader region filtering remains separate design work.
  Completed selections: **194 passed**, **51 deselected**, dependency warnings.
  Two sandbox-blocked localhost tests passed on rerun with socket access. One
  Zarr round trip timed out; two existing typing errors reproduce in pre-rename
  snapshots. See the [rename record](plans/2026-11-06-georegion.md) for limits.

- [x] **ODC loader inputs:** both loaders accept typed `region=GeoRegion`,
  explicit CRS/resolution/pixel anchor or an exclusive exact GeoBox. Region time
  filters overlapping Items without rewriting dates. Grouping defaults to
  `"id"`; mosaicking is explicit. Removed raw geometry aliases and redundant
  extent conversion. ModelSpec retains its own explicit solar-day default.
  E3 and E5 remain open: requested-region retention does not define source Item
  geometry propagation. See the [loader record](plans/2026-11-06-odc-loader.md).

The grid locates pixels; the declared extent describes a place. Spatial slicing
retaining the declaration is intentional. Do not replace all regions with grids.

## Catalog and sampling

- [x] **V1/V2 — Old pairing collision/mechanism superseded.** Calendar sampling
  uses long-form collection identity and separate `read_observations`,
  `assign_slots`, and `select_windows` operations. No nearest-date pairing stages

- [x] **V3 / #24 — Founding footprints retained.** Planned GeoSamples carry the

  intersection fallback. Chips takes prepared Datasets and never chooses a Region,
  resolution, union grid or per-chip reprojection.
- [x] GeoSamples copies the catalog table to protect row positions after source
  edits. Nested asset dictionaries remain shared; this is not a recursive snapshot.
- [x] Calendar selection uses `date_range` bounds and explicit frequency anchoring;
  calendar frequencies such as MS keep their calendar boundaries. Earlier
  earliest-observation anchoring and separate start/end proposals are obsolete.
- [x] **#25 superseded:** interval-only observations now have explicit calendar
  assignment policies. Do not restore the older representative-start pairing rule
  as the universal sampling interpretation. Full interval coverage remains distinct.
- [ ] **V4 — Temporal validity across consumers.** Vector time helpers now
  share STAC `read_timespan`, but validation remains separate: the reader can
  fill partial bounds and does not reject reversed bounds (`stac/item.py:327-342`). Reproduce reversed/partial bounds,
  UTC offsets and timeless cases; unify validity where appropriate while retaining
  overlap queries, calendar membership and extent envelopes as different operations.
- [x] **V5 — Native Item I/O ownership and API.** The accessor already delegated
  I/O; the former ownership finding was stale. Public `io.open_item` replaces
  `open_scene`. Removed public `open_items` / `open_collection` and consolidated

  Native `rows.gs.to_datatree()` remains necessary: `ModelSpec.prepare` uses it,
  and ODC replacement changes independent grids, temporal bounds, timeless
  representation and sometimes dtype. See the reproducible
  [feasibility study](benchmarks/2026-11-06-native-open/index.md).
  Full migration to ODC requires separate contract decisions; it is not complete.
  Verification: **143 passed** across completed selections, **31 deselected**;
  one schema-fetch failure passed with network access. Targeted lint and API
  freshness passed; one unchanged asset-reader typing diagnostic remains.
- [ ] **V6 — Footer/schema ownership.** Collection parsing survives in both
  `core/vector/catalog.py:331-340` and `io/formats/stac_geoparquet.py:217-237`;
  StacTable now delegates to the latter. Distinguish accessor eligibility,
  full Item validation, and writer loss prevention. First-Collection-definition precedence is an existing
  behavior, not a refactor bug to silently change.
- [x] **#15:** Collection metadata is acquired once per table search.
- [x] **#21 obsolete:** moving all sampling based on file length was withdrawn.
- [x] **#30:** native exact-grid reads and explicit ODC target-grid loading are
  documented separately. Shifted native grids need explicit loading preparation,
  not an automatic resampling wrapper around the reader.

- [ ] **V7 — Vectorization mask axes, reproduced.**
  `transform/vector.py:160-170` checks equal GeoBoxes but reads mask values without
  arranging axes. For values `[[1,2],[3,4]]` and mask
  `[[False,True],[False,False]]`, the normal mask selects value 2; the same mask
  transposed to `(x,y)` selects value 3. Align named mask dimensions before
  rasterization, or explicitly reject incompatible ordering before reading.
